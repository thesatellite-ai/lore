# J4 — a lore 0.1.17 user upgrades

**Who.** Ola, who used lore 0.1.17 for months on three repos under `~/code`: `app` (a day-to-day project, 176 rows), `big` (the 5.5k-row repo: tasks, comments, commit links, memories) and `brick` (code only, no lore data). Their `.lore/data` holds exactly what 0.1.17 wrote (format 1: `"_v": 1` rows, `_meta.json`, the 0.1.17 `.gitignore` block), generated by `V017Repo`. Ola installs this lore. Every name is made up.

**Test.** `TestStoryJ4Upgrade` (`j4_upgrade_test.go`).

## Steps

1. Day 1: Ola clones the three repos and reads: `lore task list --all` shows every task of `app` and of `big` (the big one in a few seconds), with one line saying the project is on the lore 0.1.17 format and `lore migrate run` upgrades it. `lore migrate status` says the same. Nothing tracked changes.
2. Ola tries a write (`lore memory add --body …`): it is refused with that one line, and nothing is written.
3. Ola commits code in `app` with plain `git commit`: lore's hooks pass it and touch no row file.
4. Day 2: `lore fix --dry-run` changes nothing and reports no failed step. `lore fix --all --yes --dirs ~/code` finds `app` and `big`, lists each as still on the old format with its `lore migrate run`, migrates nothing, and leaves `brick` byte-identical.
5. Day 3: Ola runs `lore migrate run` in `app`. It upgrades every row, records the format with who and when in `_meta.json`, leaves the `.0-needs-lore-0.1.18-or-newer` signpost for teammates still on 0.1.17, commits nothing itself, and prints the one `git add .lore/data && git commit` to make. Ola makes that one commit; every task is still there; `big` stays on the old format.
6. Writes work again in `app`; nothing is pushed until Ola's own `git push`, which carries the migration to main.

## What must hold

- Old-format projects stay old until a person runs `lore migrate run`: every read, refused write, hook, `lore fix --dry-run` and `lore fix --all` leaves every row file at `"_v": 1`; migrating one project never touches another.
- Nothing pushes without push or sync: no remote ref of the three repos moves until Ola's `git push`.
- A repo without lore data stays byte-identical (`brick` under `lore fix --all`).
- Named flags in every hint (the refusal, fix --all, migrate run).
- No row is lost: the task counts before and after the migration match.

# Migration prompt — onboard any existing repo onto lore

**In short:** this page is one long message you paste into your coding agent. The agent then moves the notes you already keep (rule files, instruction files, an `.ai/` folder) into lore, one step at a time, and asks you before each step.

Copy-paste this prompt into a new session of your coding agent, opened inside a repo you want to migrate. Repo-agnostic; works for repos using codeskill, hand-written CLAUDE.md, AGENTS.md, .cursorrules, an `.ai/` directory, or any combination.

---

```
I want lore to be the single source of truth for project knowledge,
memories, rules, decisions, hotfixes, patterns, and tasks in this repo. Walk
me through migrating from whatever I'm using now (CLAUDE.md generated by
codeskill, hand-written AGENTS.md, .cursorrules, .ai/ directory, etc.) onto
lore.

## Hard rules

- The `lore` skill is installed (at `~/.claude/skills/lore/`)
  and `lore` is on `$PATH`. Verify before starting. If missing, stop
  and tell me how to install.
- Don't push, don't commit, don't delete anything without telling me first.
- Backup any file you're about to overwrite (e.g. `CLAUDE.md.bak.<date>`).
- After every step, show me the result and pause for confirmation before
  the next step.

## Step-by-step plan (run each one at a time, ask me before the next)

### 1. Survey what's already here
- Is `.lore/` initialized? (`ls .lore/`)
- What agent instruction files exist? (`ls CLAUDE.md AGENTS.md .cursorrules .ai/`)
- If `.ai/` exists, what markdown files are in it? Identify the canonical
  ones (RULES, HOTFIXES, PATTERNS, ARCHITECTURE, taste, STACK).
- Is `CLAUDE.md` generated by another tool? (Check for header comments like
  `<!-- GENERATED FILE — do not edit directly. Run /codeskill sync -->`)
- Report the findings before doing anything.

### 2. Initialize lore
- `lore init` (refuses if `.lore/` exists — say so).
- Verify: `lore doctor`.

### 3. List candidates from existing `.ai/` docs
- Read the canonical files section by section and list each section as a proposed rule, decision, memory or hotfix (lore 0.1.18 has no automatic importer).
- Show me the list with its source file and heading.
- DO NOT add anything yet.

### 4. Review & add
- Drop obvious low-value items (intro paragraphs, outdated notes).
- Add the rest with the matching command (`lore rule add`, `lore decision add`, `lore memory add`, `lore hotfix add`).
  You can promote-to-rule later.
- Verify: `lore memory list`, `lore rule list`, `lore decision list`.

### 5. Capture an "always use lore" meta-rule
- `lore rule add --severity=must "ALWAYS use the lore skill
  bundle for session memory, captures, decisions, hotfixes, patterns, and
  renders. After every capture, run lore render. Supersedes any
  prior session-management tool."`

### 6. Preview the render
- `lore render --target=CLAUDE.md --dry-run`
- Show me the output. If a prior tool generated `CLAUDE.md`, point that
  out — back it up before overwriting:
  `cp CLAUDE.md CLAUDE.md.<old-tool>.bak`

### 7. Overwrite CLAUDE.md (after my confirmation)
- `lore render --target=CLAUDE.md`
- Verify file header now reads "generated by lore render".
- Tell me what content was LOST vs. the backup so I know what to manually
  re-capture if I care about it.

### 8. Disable any conflicting auto-sync from the prior tool
- If a hook / cron / pre-commit / task auto-regenerates `CLAUDE.md` from
  some other tool, find and disable it (don't leave a battle for ownership).
- Common offenders: `/codeskill sync`, custom `task render` aliases,
  pre-commit hooks regenerating from `.ai/RULES.md`.

### 9. Suggest immediate hand-edits I should consider
- Memories that are clearly rules → promote via:
  `lore rule add --severity=must "<text>"; lore memory archive --id mem_<id>`
- Memories that are clearly hotfixes (recurring traps) → same shape with
  `hotfix add --severity=high`.
- Print 3-5 specific suggestions based on what was imported.

### 10. Final state report
- Count of memories / rules / hotfixes / patterns in the DB.
- Confirm CLAUDE.md is owned by lore.
- List any files in the repo that still reference the old tool's command
  names (so I can clean them up later).

## Known v0.1 gotchas (mention these proactively if you hit them)

- The notes are the files in `.lore/data`; commit them. lore's cache
  is outside the repo (`~/.lore/cache/repo/<folder>-<hash>.db`) and is
  rebuilt from those files, so there is no database to back up.
- `--scope foobar` and other invalid enum values: the skill bundle says to
  surface the error rather than forward.

## When you're done

End with one paste-ready command block I can use to capture more knowledge
the natural way (no `lore` jargon — just normal English I'd say,
followed by the command the skill should emit). Something like:

> "Remember: <X>" → `lore memory add --body "<X>"; lore render`
> "We always <X>" → `lore rule add --severity=must "<X>"; lore render`
> "We keep hitting <X>" → `lore hotfix add --severity=high "<X>"; lore render`
> "We decided <X> because <Y>" → `lore decision add --title="<X>" --body="<Y>"; lore render`

That way I have a cheat-sheet I can refer back to.
```
